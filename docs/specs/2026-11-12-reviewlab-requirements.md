# ReviewLab 需求说明

状态：已确定。日期：2026-11-12。产品行为以这份为准。

2026-11-21 修订：§7 和 §8 按课程的新规定放宽了对组件库和 AI 生成代码的限制，其余条款未动。

这是单人课程项目 ReviewLab 要做成什么样。源文件如何拆分、使用哪一个路由库、SQL 如何书写，不属于产品行为，本文件不规定。

学生：Huang Haoran（24101322D）。一人完成。

## 1. 产品

用户把学习材料收成一棵文件夹和卡片的树。当前层像桌面上的图标一样平铺。进入 Focus 后，一项占住屏幕的主要区域。卡片用来回忆标题背后的内容，并标出是否掌握。统计视图给出当前层的完成率，以及未掌握的卡。Ctrl+K 在屏幕中间打开搜索，用来跳到树上的任意一项。

一个新用户只凭界面就能完成：打开一层、进入 Focus、翻转一张卡、标掌握或未掌握、改一张卡的标题和正文、新建并删除一个文件夹、刷新后看到刚才的结果、打开统计并跳回未掌握的那一张、用搜索打开另一层里的一张卡。

## 2. 不做

- 账号、登录、多人各自的树
- 间隔重复、到期提醒、学习计划
- 有独立地址的搜索页、设置页、独立的编辑页
- 把子文件夹里的卡片算进当前层的统计
- 拖拽改变排序
- 把卡片挪到另一个文件夹，或给文件夹改父级
- 原生手机应用
- WordPress、Wix 或其他建站工具

空文件夹、删除确认、卡片正反面、白昼和暗色、搜索层，都是状态，不是新的视图。

## 3. 三个视图

本节的 Focus 在 2026-11-21 改名为「禅模式」，本节的「文件视图」改称普通视图。这两个视图的形态由 `2026-11-21-reviewlab-file-overview-spec.md` 改写，冲突时以那份文档为准；本节其余条款继续有效。

三个视图各自有地址。刷新或把地址发给别人，打开的仍是同一个文件夹、同一种视图。Focus 的地址还要落到当前这一项。搜索层没有地址。刷新之后搜索层是关上的。

课程要求从手机到桌面都能操作。这里的范围是浏览器宽度 360px 到桌面。三个视图在这个范围内都能完成第 1 节里的那条路径。搜索在这个范围内也要能打开。

### 文件视图

显示当前层，文件夹和卡片平铺，两者一眼能分开。顺序按创建时间从早到晚。创建时间相同的，按先写入的在前。刷新后顺序不变。

在这一层可以：

- 创建文件夹。创建时填写名字，留在文件视图。去掉首尾空白后名字不能为空，且不超过 120 个字符。不满足时不创建，并说明原因。
- 创建卡片。创建后立刻进入 Focus，落在这张新卡上。标题固定为 `New page`，正文为空。
- 给文件夹改名，给卡片改标题。不能在这里改正文。
- 删除文件夹或卡片。删除前要确认。确认文案分别写出将去掉的文件夹数量和卡片数量，被选中的那一项自己算进去。删掉一个文件夹时，它下面所有层级的文件夹和卡片一起去掉，并计入这两个数。确认后才删除。取消或 Esc 不删除。
- 点一个文件夹，进入它的那一层。
- 进入当前层的 Focus。当前层没有任何项时，这个操作不可用。有项时，落在创建时间最早的那一项。
- 打开当前层的统计。
- 打开搜索。

最外层文件夹可以改名，不能删除，也不能改成没有父级。其他文件夹创建之后，父级也不再改变。卡片创建之后，所属文件夹不再改变。

同一层允许同名。比较时不去掉大小写差异，只按各自保存的名字判断是否为同一项。

### Focus

一次只看当前层里的一项，卡片或文件夹。这一项占屏幕的主要区域。切换只在当前层里循环：最后一项的下一项是第一项，第一项的上一项是最后一项。顺序与文件视图相同。

- ArrowLeft 上一项，ArrowRight 下一项
- 拖拽把当前项带走，任意方向松手都与 ArrowRight 相同，换成下一项。没有完成的拖动回到原位。
- 当前是卡片时，Enter 在标题和正文之间切换。点击卡片上的标题或正文区域，做同一件事。
- 当前是文件夹时，显示文件夹的名字，没有正反面。Enter 进入该文件夹的文件视图。
- Esc 回到上一层的文件视图。已经在最外层时，Esc 留在原地。
- 正在输入标题或正文时，方向键、Enter、Esc 只作用于输入，不切换项，不离开 Focus。Esc 结束输入。

卡片的标题和正文都在 Focus 里改。文件夹不在 Focus 里改名。

当前层没有任何项时，不能进入 Focus。

### 统计

只统计当前层的卡片，不算文件夹，也不算更深层的卡片。

- 已标记张数 = 掌握张数 + 未掌握张数。
- 完成率 = 已标记张数 / 本层卡片张数。有卡片时显示四舍五入到整数的百分比，并同时写出分子和分母。全部未标记时显示 0%。
- 本层没有卡片时，不显示 0% 或除零，显示这一层没有卡片。
- 未掌握的卡按创建时间从早到晚列成清单。点一条，打开 Focus 并落在那一张上。
- 未标记的卡不是错误，不进这张清单。
- 数字由每张卡当前的状态算出。不另存一轮历史。

### 搜索

Ctrl+K 打开搜索，再按一次关掉。macOS 上 Cmd+K 做同一件事。三个视图里都有一个搜索按钮，效果与 Ctrl+K 相同，360px 宽度下用触摸也能打开。

搜索是盖在当前视图中间的一层，底下的视图保持原样。点击这一层以外的区域关掉它。关掉之后，仍停在打开它之前的视图和那一项。搜索打开时，方向键、Enter、Esc 只作用于搜索。

- 输入框获得焦点，键入的文字不写进底下的卡片。
- 正在编辑标题或正文时按下 Ctrl+K 或 Cmd+K：已有修改且合法，先保存，再打开搜索。修改不合法，不打开搜索，并说明原因。
- 删除确认开着时，Ctrl+K 和 Cmd+K 不打开搜索。Esc 只取消删除。
- 搜索开着时，Esc 只关闭搜索。

输入去掉首尾空白后为空时，列出全部文件夹和卡片，包括最外层。按最后修改时间分组，组别顺序为今天、昨天、更早。没有项的组别不显示。组内按最后修改时间从新到旧。时间相同的，按创建时间从早到晚。今天和昨天按这台浏览器的本地日期计算。

输入去掉首尾空白后不为空时，只列出匹配项，分组规则与上面相同。匹配是不区分大小写的子串，范围是整棵树：文件夹看名字，卡片看标题和正文，包含更深层。没有匹配时显示「没有结果」。

每一行显示该项的图标、名字，以及路径。路径是从最外层到它的父文件夹，名字用「 / 」连接。最外层的直接子项，路径只有最外层的名字。最外层自己那一行不显示路径。

打开时选中第一行。ArrowUp、ArrowDown 移动选中行，到头就停，不循环。Enter 或点击打开选中行。没有行时，Enter 什么也不做。

- 打开文件夹：关闭搜索，进入该文件夹的文件视图。
- 打开卡片：关闭搜索，进入这张卡所属文件夹的 Focus，并落在这张卡上。

不做「仅搜标题」「创建者」「在页面中」「筛选」。不做在新标签页打开、复制链接、命令搜索。

## 4. 掌握

每张卡只有三种状态：未标记、掌握、未掌握。新卡是未标记。

展示一张卡时，卡的下方有两个按钮：掌握、未掌握。按钮下方有两个数，左是当前层掌握的张数，右是当前层未掌握的张数。当前项是文件夹时，不显示这两个按钮，也不显示这两个数。

这两个数是状态的张数，不是点击次数。

- 未标记时点其中一边：那一边加 1
- 已经是某一边时再点同一边：两个数都不变，这张卡的状态也不变
- 从一边改到另一边：原来那一边减 1，新的一边加 1

刷新之后，状态和这两个数仍然一致。

## 5. 数据

两个实体。

- 文件夹：名字，父文件夹，创建时间，最后修改时间。最外层没有父文件夹。
- 卡片：标题，正文，所属文件夹，掌握状态，创建时间，最后修改时间。

卡片必须属于一个文件夹。

名字和标题去掉首尾空白后不能为空，长度不超过 120 个字符。正文允许为空，长度不超过 4000 个字符。长度按去掉首尾空白之后计算，一个码位算一个字符。保存时写入去掉首尾空白后的文字。不满足时不保存，并说明是空的还是超过上限。

最后修改时间在创建、改名、改标题、改正文、改掌握状态时更新。搜索的分组用这个时间。统计不使用它。

树、掌握状态、创建时间和最后修改时间保存在 Supabase 的数据库里。刷新、关掉页面、换一台电脑打开同一个部署地址，看到的是同一棵树。主题不进数据库。搜索的输入不进数据库。

种子数据是假的课程材料，没有真实姓名、密码或支付信息。种子里要有：一个最外层文件夹、至少一个子文件夹、至少三张卡片。这三张里，掌握、未掌握、未标记各至少一张。至少一张卡片的正文不是空的。至少一张卡片放在子文件夹里。

这个部署没有登录。知道地址的人都能改这棵树。报告里要把这一点写成已知限制。

## 6. 主题

White 和 Dark 两套，全局生效。文件视图、Focus、统计、搜索层、删除确认共用。同一台浏览器上，刷新后主题保持。换一台浏览器不跟随。三个视图里都能切换，切换立刻作用到上面这些地方。

界面上的图标使用 [Hugeicons](https://hugeicons.com/) 的 React 包 `@hugeicons/react`（免费包，MIT）。图标只表示文件夹、卡片、掌握、未掌握、收藏、创建、编辑、删除、主题、搜索和关闭，不承担页面逻辑。

## 7. 前端组件

界面是 React 应用，部署在 Vercel。浏览器通过 Supabase 读写数据。

[React Bits](https://reactbits.dev/get-started/introduction) 及其它开源组件库都可以用，用来承担视觉表现和交互动效。课程全面接受 AI 辅助生成的代码，组件的挑选、接线和行为由学生决定。

复制的组件要照实申报：每复制一个组件，报告和 `ai-use.md` 都要记下组件名、作者、许可证和所在文件。`@hugeicons/react`、`motion`、React、Supabase 的客户端以依赖形式使用，同样在报告里申报许可证。不使用 React Bits Pro，也不使用整页模板。

表、约束和访问规则放在 `source/database` 与 `source/server`，学生要能解释它们。

已交大纲里写的是无构建步骤的原生 HTML。现在改为 React。若老师或 tutor 认为这是范围变化，发邮件说明。

## 8. 和评分的对应

| 课程底线（单人） | 本需求 |
|---|---|
| 至少 3 个功能视图 | 文件视图、Focus、统计。搜索层不是第四个视图 |
| 至少 2 个数据实体 | 文件夹、卡片 |
| 至少 2 条完整增删改查 | 文件夹一条，卡片一条。读是打开当前层，以及在 Focus 里打开一张卡 |
| 刷新后数据还在 | 树和掌握状态在 Supabase |
| 非法输入有处理 | 空名称不保存，超长不保存，删除要确认 |
| 响应式 | 浏览器宽度 360px 到桌面。不做原生应用 |
| 服务端与数据 | 表、约束和访问规则放在 `source/database` 与 `source/server`。学生要能解释 |
| AI 协助 | 课程全面接受 AI 辅助生成的代码。AI 写过或改过的文件在 `ai-use.md` 和报告里逐个申报；复制的第三方组件另外申报组件名、作者和许可证 |

## 9. 已经确定的决定

1. 最外层文件夹不能删除，可以改名。
2. 左方向键是上一项，右方向键是下一项。拖拽松手后等同于右方向键。
3. Focus 的循环包含当前层的文件夹和卡片。
4. 卡片创建后进入 Focus，标题为 `New page`，正文为空。正文只在 Focus 里改。标题在 Focus 和文件视图里都能改。文件夹的创建、改名、删除，以及卡片的删除，在文件视图。
5. 顺序按创建时间从早到晚，不能拖拽重排，也不能改父级或所属文件夹。
6. 统计不保存每一轮的历史，只反映当前状态。
7. 没有登录，部署地址上是同一棵共享的树。
8. 搜索是屏幕中间的一层，搜整棵树，没有自己的地址。
9. 同一层允许同名。
10. React Bits 及其它开源组件库都可以用，用在视觉表现和交互动效上；复制的组件逐个申报组件名、作者和许可证。
