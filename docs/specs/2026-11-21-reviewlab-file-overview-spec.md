## 1. 这一轮要解决的问题

现在的界面（`docs/articrafts/before-fileview-1440.png`）有几个具体毛病：

- 侧栏的 "Create card" 和标题栏的 "Create folder" 被拆在两个地方，"Search" 出现两次。
- 五个动作按钮视觉权重完全一样，主流程和破坏性操作并列。
- 卡片 tile 只有标题，看不出掌握状态——而掌握状态是这个产品唯一的数据。
- 文件夹名在界面上出现两次（图形上的标签页 + 图下面那行文字）。
- 卡片右上角的角标菜单实际落在左上角，还占着布局流（`CardMenu.css` 写了 `.card-menu` 绝对定位，`CardMenu.jsx` 没有渲染这一层）。
- 没有面包屑。侧栏只显示两级，跳进第三层以后你在树里的位置在界面上不可见。
- 360px 下侧栏堆在内容上方，首屏 290px 全是侧栏。
- `1 folders, 3 cards.` 的单复数没处理。

新形态要解决的就是这些：把「这一层有什么、我在哪、我复习到哪儿了」三件事在**一屏之内**说清楚。

## 4. ArcGallery —— 共享的卡片画廊

这是本轮最核心的新组件，两个视图共用。

### 4.1 两个缩放档

| 档 | 状态 | 样子 |
|---|---|---|
| **聚焦** `focused` | 一张卡占主要区域 | 卡片居中放大，周围卡片隐去，但弧形的空间感保留（背景仍有弧形曲率）。 |
| **全景** `overview` | 整层的卡片排成横向弧线 | 卡变小、沿弧线排开，中间平两侧外倾，边缘淡出。 |

- 缩放是一个**连续参数** `t ∈ [0,1]`：`t = 1` 是聚焦档，`t = 0` 是全景档。**每张卡各自**按 `t` 算自己的位置、缩放和透明度——当前卡在正中最前，其余卡按到中心的距离依次沿弧线排开并淡出。不是两套画面切换，也不是同一个元素的 transform 插值。
- 普通视图**固定在聚焦档**（`t = 1`），外面套着顶栏、左栏、右栏、Dock。
- 禅模式**两档都能到**：捏合缩小从聚焦退到全景，捏合放大或点一张卡从全景进聚焦。

### 4.2 卡片

- 卡片本体是 FlipCard（DOM + 3D），正面问题、反面内容。FlipCard 从 React Bits 抄，它依赖 `motion` 这个包（见第 17 节）。
- **正面**：只显示问题（卡片的 title）。
- **反面**：显示具体内容（卡片的 body）。正文为空时显示 `This card has no content yet.`，不是一片空白。正文超长时**反面内部可滚动**，不撑破卡片。
- 点击翻面。`Enter` 也翻面。
- 拖动卡片可以横向甩，松手切换到下一张（和现在的 Focus 一样：松手等同 ArrowRight，拖到一半松手回原位）。**FlipCard 自带的拖拽要关掉**（`draggable={false}`）——它自带的横向拖拽是"翻面"，我们要的是"切下一张"，所以甩动手势由画廊自己实现。
- 弧形排布：卡片沿一段圆弧分布。弧的曲率随缩放档变化——聚焦时几乎看不出弧度，全景时弧度明显。

### 4.3 切换

- `ArrowLeft` / `ArrowRight`：上一张 / 下一张，在**本层的卡片**里循环。文件夹不参与。
- 触控板：横向拖动可以甩动，惯性滑行，松手吸附到整张。
- 捏合缩放走两个通道，都要 `preventDefault`（否则浏览器自己缩放了页面）：
  - 触控板双指 = `wheel` 事件带 `ctrlKey`。
  - 触屏双指 = `touchstart` / `touchmove`，自己算两指之间的距离变化。
- 捏合在聚焦档和全景档之间连续过渡。**普通视图不接捏合**（它固定在聚焦档），禅模式才接。
- 点击：全景档里点一张卡 → 放大聚焦它；聚焦档里点卡 → 翻面。

### 4.4 数据

画廊的内容就是**当前层里的卡片**，按创建时间从早到晚。文件夹不进画廊——文件夹在左栏单独一行。

## 5. 普通视图

### 5.1 顶栏

| 位置 | 元素 | 规格 |
|---|---|---|
| 左 | 搜索按钮 | 白色圆角胶囊 + 细线放大镜图标，文字 `Search`。点击打开搜索层，行为与 `Ctrl+K` 完全相同。 |
| 中偏左 | 标题 | 当前层名字，34px 半粗。 |
| 中偏左（第二行） | 面包屑 | `root › Software Engineering`，13px，浅灰。路径**从最外层到当前层**，最后一段是当前层（不可点），前面每一段可点跳到那一层。 |
| 中偏左（第二行右侧） | 计数 | `1 folder · 4 cards`，比面包屑更浅。单复数要处理。 |
| 右 | 主题开关 | 白色胶囊开关，旋钮在左 = 浅色主题。点击立即切换，作用于全部界面（普通视图、禅模式、统计、搜索层、删除确认）。 |

顶栏不放 Create / Focus / Statistics / Search 的文字按钮行。

**当前层改名**：双击顶栏的标题进入编辑，规则跟卡片标题一样（去空白后不能为空、≤120 字符）。最外层文件夹可以改名，不能删除。

### 5.2 左栏

宽约 220px，三段，从上到下。

**(a) 文件夹行**

当前层的子文件夹以紧凑条目列出（图标 + 名字），一行一个。点击进入那一层。文件夹不参与弧形廊。

每个文件夹条目有两个入口：

- **双击条目（或双击它的名字）** = 改名。规则跟卡片标题一样（去空白后不能为空、≤120 字符）。
- 条目右侧一个垃圾桶图标按钮 = 删除。点了走删除确认（见第 9.3 节）。最外层文件夹不显示这个按钮（它不能删）。

文件夹的**创建**在 Dock 的「创建」里（见第 9.1 节）。

**(b) 卡片轮盘**

当前层里的卡片，沿**一段圆弧**排开。这段弧的**圆心在屏幕左侧之外**，所以看到的是**右半圆**：当前聚焦的那张在最右边，从它往上下两端走，卡片逐渐向左退，最后退出屏幕左缘。

- 几何（照 React Bits `OptionWheel`）：所有卡片坐在同一个圆上，圆心在锚点左侧 R 像素处，`R = 行高 / tan(切角)`。切角 6°、行高约 70px 时 R ≈ 640px；锚点离屏幕左边约 200px，所以圆心整个跑到屏幕外。
- 卡片跟着弧的切线转：离锚点越远转得越多（每离开一格转 6°）。
- 离锚点越远越淡（透明度递减），并且轻微模糊。
- 每张：左边细线卡片图标，中间单行省略的标题，右边一个状态点。
- 状态点：实心绿 = 掌握，实心红 = 没掌握，空心灰 = 未标记。
- **当前聚焦的那张**完整露出，带一圈 2px 蓝色描边。
- 点击轮盘里的某张卡 → 画廊聚焦它。
- 轮盘可以沿弧线拖动（甩动切卡），滚轮也能转。
- 轮盘是**导航器**，不是另一个卡片浏览器；正反面不在这里翻。
- 实现上抄 React Bits `OptionWheel`（见第 17 节），把它的文字条目换成卡片内容。

**(c) 掌握圆环**

见第 8 节。轮盘正下方。

### 5.3 右栏

靠屏幕右边缘的一条窄竖栏，从上到下两个位置：

1. **收藏位** — 一个星形图标 + 本层的收藏数量。这一轮**只做成只读占位**：显示数量，**不做过滤**（规格 P4 待设计）。星形图标在这里表示"这一层有几张被收藏了"，不表示当前卡是不是收藏状态；当前卡的收藏状态看 Dock 的星标和卡上的星标。
2. **禅模式入口** — 点击进入禅模式。

### 5.4 Dock

底部居中悬浮的白色长条胶囊。

| 按钮 | 作用 |
|---|---|
| 收藏 | 切换当前大卡那张卡的收藏状态 |
| 创建 | 打开新建流程（第 9 节） |
| 编辑 | 从**侧边**滑出编辑窗，编辑当前大卡那张卡的标题和正文 |
| 删除 | 打开删除确认（第 9 节） |

- Dock 默认显示，**向下滚动就向下滑出屏幕**，向上滚回来或**鼠标移到底部边缘**就重新出现。主区（卡片那一片）是滚动容器，滚动的是它，不是整个页面。
- Dock 藏起来的时候，四个动作不会失联：鼠标移到底部它就回来，键盘用户可以用 `Tab` 聚焦到它，顶部搜索和主题开关也一直都在。
- 图标是统一的细线图标，悬停时放大一点点并浮起。
- 每个图标下面有一个很小的灰色文字标签：`Favorite` / `Create` / `Edit` / `Delete`。

## 6. 禅模式

- 路由有两条：`/zen/:folderId`（不定位到某一张）和 `/zen/:folderId/:itemId`（聚焦到那一张）。
- 全屏，**去掉一切外围**：没有顶栏、没有左栏、没有右栏、没有 Dock、没有面包屑。只有弧形廊和卡片。
- **右上角三个极简图标按钮**，从左到右：放大镜（打开搜索层）、主题开关、叉号（退出）。它们要小、淡，不破坏沉浸感，但**必须有**——基准规格要求三个视图里都能切主题、都能打开搜索，而 360px 的触摸用户没有 Ctrl+K。
- 叉号点了退出，`Esc` 也退出。退出 = 回到 `/folder/:folderId/:itemId`（当前聚焦的那张；没有卡片时回 `/folder/:folderId`）。
- **谁落到哪一张**：
  - 从普通视图的右栏入口进来 → 聚焦普通视图当前那张卡。
  - 从地址 `/zen/:folderId/:itemId` 进来 → 聚焦那一张。
  - 从地址 `/zen/:folderId` 进来，或者刷新 → 落在本层最早创建的那张卡。
- **在禅模式里切卡不改地址**。地址只在"从外面跳进来要落到某一张"的时候带卡片 id；切卡是瞬时状态，不写进地址。
- 禅模式里只有**卡片**，没有文件夹。文件夹不参与弧形廊，也不参与方向键循环。
- 掌握和收藏这两个动作在禅模式里**不做**（没有 Dock、没有按钮）——那是普通视图的事。禅模式只负责安静地过卡。
- 统计页面的圆环在这里不出现。
- **搜索在禅模式里打开一张卡** → 关闭搜索，进入 `/zen/:folderId/:itemId`，落在那一张上（基准规格 §3 搜索的规则）。
- 主题开关切了之后，普通视图、禅模式、统计、搜索层、删除确认五处一起变。

## 7. 统计视图

- 路由 `/stats/:folderId`。
- **圆环是同一个组件，只是尺寸大**。内容和小圆环完全一致：左 Master、右 Not Mastered、中心是同一个比例数字。
- **从普通视图点小圆环，直接进入统计页面**。
- 统计视图保留三个功能视图的位置（普通视图 / 禅模式 / 统计），满足课程「至少 3 个功能视图」。
- **统计页面的具体排版待设计**（第 14 节）。已经定死的只有：圆环放大居中，以及它跟小圆环是同一个组件。

统计视图里除了圆环，至少还要有现行规格要求的两样东西：

- **完成率** = 已标记张数 / 本层卡片张数，写出分子和分母。本层没有卡片时显示「这一层没有卡片」，不显示 0%。
- **未掌握的卡的清单**，按创建时间从早到晚。点一条进入 `/zen/:folderId/:itemId`，落在那一张上（基准规格 §3 统计的规则）。

注意两个口径不同，别混：

| 指标 | 分母 | 在哪 |
|---|---|---|
| 掌握占比（圆环） | 已标记的卡 M + N | 普通视图左下的小圆环 / 统计页面的大圆环 |
| 完成率 | 本层全部卡 | 统计页面 |

## 8. 掌握圆环（CometDial）

几何照 React Bits `CometDial` 的形状。

### 8.1 画法

- 一个圆环，描边无填充，**底部留 90° 开口**（6 点钟方向）。
- 圆环总弧长 **270°**。弧起点在**左下 7:30**，弧终点在**右下 4:30**，沿左侧 → 正上 → 右侧顺时针扫过。
- **彗头**是一个实心圆点，落在弧上。
- **绿色弧**从弧起点到彗头，**红色弧**从彗头到弧终点。两段弧首尾相接，铺满整个 270°。
- 中心显示一个数字，就是掌握占比。
- 左边标 `Master`（绿），右边标 `Not Mastered`（红）。
- **圆环下方还有两个数**：左边是绿色的 **M**（本层掌握的卡数），右边是红色的 **N**（本层没掌握的卡数）。基准规格 §4 要求这两个数看得见，所以不能只留百分比。
- 颜色用固定色值，不走主题 token，保证两套主题下对比度都够：掌握绿 `#16a34a`、没掌握红 `#dc2626`、空态的轨道中性灰 `#9ca3af`。文字用主题 token。

**这个圆环是 React Bits `CometDial` 的抄件**，几何直接用它（`sweep = 270` 时它的起点正好是 135°、终点 45°、底部 90° 开口，跟第 8.2 节的公式逐字等价）。抄过来之后改三处：

1. 加一个 `restColor` prop：给了就用这个颜色画轨道且**不透明度为 1**（实弧）；不给就是原版的中性灰淡轨道。空态时不传 `restColor`。
2. 加一个 `readOnly`：挡住拖拽和键盘，但**不加**原版的 `data-disabled`（那个属性会把整个圆环变暗 0.55）。`aria-disabled` 和 `tabIndex={-1}` 照旧。
3. `readOnly` 时不要给 svg 加 `pointer-events: none`，要让外层包着的按钮能收到点击。

它的拖动交互不要（那是个可拖的滑块，会回写 value），我们要的是数据驱动 + 点击进统计页。

### 8.2 算法

```
M = 当前层里状态为「掌握」的卡片张数
N = 当前层里状态为「没掌握」的卡片张数
p = M / (M + N)          （M + N = 0 时 p 取 0）

彗头极角 θ = 135° + p × 270°        （SVG 极角，0° 在 3 点钟方向，顺时针为正）

  p = 0     → θ = 135°   彗头在 7:30，绿色弧长度为 0
  p = 0.5   → θ = 270°   彗头在 12:00，正上，左右各占一半
  p = 1     → θ = 405°   彗头在 4:30，绿色弧铺满整个圆环
```

### 8.3 四条规则

| 规则 | 几何里对应什么 |
|---|---|
| 勾选 Master：绿色线在整个圆圈横向延伸，直接到达右边 | N = 0 → p = 1 → 红色弧长度为 0，绿色弧铺满 270°，彗头推到右下终点 |
| 点击 Not Master：左右各占 50% | M = N → p = 0.5 → 彗头在 12:00，绿弧盖左半、红弧盖右半 |
| 最终状态：圆点到两边的长度代表相对比例，中间数字只显示这个比例 | 彗头到两端的弧长比 = M : N；中心数字 = `round(p × 100)%` |
| 初始数字为 0；用户什么都没点就不更新 | M + N = 0 → 数字 `0%`，整圈中性灰，没有彗尾，**不做任何动画** |

### 8.4 状态表

| 状态 | 条件 | 绿色弧 | 红色弧 | 中心数字 |
|---|---|---|---|---|
| 空 | M + N = 0 | 无 | 无（整圈中性灰） | `0%` |
| 全掌握 | N = 0，M > 0 | 整圈 270° | 无 | `100%` |
| 全没掌握 | M = 0，N > 0 | 无 | 整圈 270° | `0%` |
| 均分 | M = N | 左半 | 右半 | `50%` |
| 一般 | 其余 | 起点到彗头 | 彗头到终点 | `round(p×100)%` |

「全没掌握」和「空」都是 `0%`，但圆环颜色不同：前者整圈是红的，后者整圈是中性灰。

### 8.5 动画

- 每次 M 或 N 变化，彗头用**弹性过渡**滑到新位置（约 400~600ms），绿弧和红弧跟着重新划分，彗尾在彗头后面拖出。
- 动画**不阻塞输入**。动画没结束就继续点，下一次从当前位置接着走。
- 数字用同样的节奏滚动到新值。
- 遵守 `prefers-reduced-motion`：用户开了减少动效时直接跳到新值，不做补间。
- 动画由**数据**驱动，不由点击事件驱动。数据变了就更新。

## 9. 写入操作

### 9.1 新建

- **新建卡片**：进入一个与卡片编辑视图相同的视图。标题预填 `New page`，正文为空。**排版待设计**（第 14 节）。
- **新建文件夹**：弹一个小窗口，上面显示 folder 图标，下面直接命名。**排版待设计**（第 14 节）。

两条都沿用现行规格的校验规则：名字去掉首尾空白后不能为空，长度不超过 120 个字符，一个码位算一个字符；不满足时不创建，并说明是空的还是超长。

### 9.2 编辑

Dock 的编辑按钮从**侧边**滑出编辑窗，编辑当前大卡那张卡的标题和正文。

- 标题和正文都在这里改。
- 标题去掉首尾空白后不能为空、≤120 字符；正文允许为空、≤4000 字符。
- 改完保存，大卡同步更新。
- 编辑窗打开时，`Esc` 关闭编辑窗。

### 9.3 删除

Dock 的删除按钮打开删除确认。

- 删的是当前大卡那张卡。删文件夹走左栏文件夹条目自己的删除入口。
- **删除前要确认**。确认文案要写出将去掉的**文件夹数量和卡片数量**，被选中的那一项自己算进去。删掉一个文件夹时，它下面所有层级的文件夹和卡片一起去掉，并计入这两个数。
- 确认后才删除。取消或 `Esc` 不删除。
- **删掉当前聚焦的那张卡之后**：聚焦同层的下一张（没有下一张就聚焦上一张），地址用 `replace` 改写成新的 `itemId`。
- 本层最后一张卡被删掉以后，这一层变成空态（见第 5 节），地址退回 `/folder/:folderId`。
- 删掉当前所在的文件夹以后，跳到它的父文件夹（现有行为）。

### 9.4 收藏

Dock 的收藏星标切换当前大卡那张卡的收藏状态。收藏状态要能在卡片上看出来。

## 10. 卡片上的掌握按钮

- 大卡上（聚焦档）显示两个圆角胶囊按钮：左边 `Mastered`（绿，对勾图标），右边 `Not Mastered`（红，叉号图标）。
- 再点当前已选的那一边，两个数都不变，这张卡的状态也不变。
- 从一边改到另一边，原来的减 1，新的加 1。
- **点一下，左下角圆环立刻动**。这是整个界面最该被看见的实时反馈。

## 11. 数据

### 11.1 变更

```sql
alter table cards add column favorite boolean not null default false;
```

- 收藏是**卡片上的一个布尔字段**，独立于掌握状态。掌握还是三种：未标记、掌握、没掌握。
- 改收藏更新 `updated_at`（搜索的分组按最后修改时间）。
- 需要一个 API 函数 `api_set_favorite(p_id uuid, p_favorite boolean)`。
- M、N、p **不另建记录表**，由卡片当前状态算出来。

改动落在这些文件里：

| 文件 | 改什么 |
|---|---|
| `source/database/schema.sql` | `cards` 表加 `favorite` 列 |
| `source/database/api.sql` | 所有返回卡片的函数（`api_list_level`、`api_get_card`、`api_list_tree`、`api_create_card`、`api_rename_card`、`api_update_card_body`、`api_set_mastery`）在返回里带上 `favorite`；新增 `api_set_favorite` |
| `source/server/policies.sql` | 给 `api_set_favorite` 加 `grant execute` |
| `source/client/src/api.js` | 加 `apiSetFavorite(cardId, favorite)` 包装 |
| `source/client/src/views/fileActions.js` | 加 `setFavorite(cardId, favorite)` |
| `source/API.md` | 端点表加一行，函数说明加一段 |
| `source/tests/cases.mjs` | 加收藏相关的检查；`FocusView.jsx` 改名禅模式后相关 import 跟着改 |

### 11.2 不变

- 两个实体还是文件夹和卡片。卡片属于一个文件夹。
- 本层的掌握数、没掌握数、完成率，全部由卡片当前状态算出。

## 12. 地址

| 视图 | 地址 | 落地到哪 |
|---|---|---|
| 普通视图 | `/folder/:folderId/:itemId` | 当前层 + 当前聚焦的那张卡 |
| 禅模式 | `/zen/:folderId` | 当前层。刷新落在本层最早创建的那张卡 |
| 禅模式（定位） | `/zen/:folderId/:itemId` | 当前层 + 指定的那张卡。搜索和统计清单用这个 |
| 统计 | `/stats/:folderId` | 当前层 |
| 搜索层 | 没有地址 | 刷新后是关着的 |

- 不带 `itemId` 的 `/folder/:folderId` 是入口，重定向到本层最早创建的那张卡。
- 禅模式从普通视图进来时带着当前那张卡，但**这个状态不进地址**，刷新后回到最早创建的那张。

## 13. 键盘、主题、响应式

### 13.1 键盘

| 键 | 普通视图 | 禅模式 |
|---|---|---|
| `Enter` | 翻面（在大卡上） | 全景档里放大聚焦当前卡；聚焦档里翻面 |
| `ArrowLeft` / `ArrowRight` | 上一张 / 下一张，本层卡片内循环 | 同左 |
| `Esc` | 关闭编辑窗 / 关闭搜索层 | 退出禅模式 |
| `Ctrl+K` / `Cmd+K` | 打开或关闭搜索层 | 同左 |

正在输入标题或正文时，方向键、`Enter`、`Esc` 只作用于输入，不翻面、不换卡、不离开。`Esc` 结束输入。

### 13.2 主题

White / Dark 两套，全局生效。普通视图、禅模式、统计、搜索层、删除确认共用。同一台浏览器上刷新后保持，换一台浏览器不跟随。三个视图里都能切换，切换立刻作用到全部五处。

### 13.3 响应式

360px 到桌面都要能完成浏览、复习、改内容、看统计、搜索。

- 禅模式在窄屏上弧度减弱（横向排不下太多卡），但捏合缩放和翻面照常。
- 普通视图在窄屏上左栏折到顶部，收藏栏折成一条窄边。
- 不出现横向滚动。

## 19. 文件概览复查（2026-11-22）

复查范围是普通视图。桌面视口 1440×900，窄屏 360×800。种子层是 Software Engineering（1 个文件夹、3 张卡：What is a requirement?、Fighter、New page）。控制台没有 error 或 warn。1440 和 360 都没有横向滚动。

### 19.1 先修

**1. 大卡正面被自己的内边距裁掉**

`.arc-gallery__face` 的计算值是 `box-sizing: content-box`，又写了 `width/height: 100%` 和 `padding: 28px`。它包在 `overflow: hidden` 的 `.flip-card__face--front` 里，卡片槽是 320×440。正面实际比槽宽出约两圈内边距。

1440 的截图里，当前卡标题画成 `What is a requiremen`，问号被切掉。量到的标题盒子右缘是 1021，裁切面右缘是 992。规格第 4.2 节：正面要完整显示问题。

**2. 掌握按钮贴在底边，点下去圆环不动**

规格第 10 节：两个胶囊在大卡上，点一下左下角圆环马上变。

长标题那张卡上，两个按钮的中心点命中的是 `.arc-gallery__stage`，不在裁切面里面。Fighter 上按钮底边和裁切面底边齐平（都是 671），命中测试能碰到按钮。对 Fighter 用 DevTools 点 `Not mastered` 之后，`aria-pressed` 仍是 false，圆环仍是 `100%`、左 1、右 0。没有控制台报错。按钮又放在 `role="button"` 的 FlipCard 里面，卡片自己的指针处理会把这一下拿走。

**3. 360px：Dock 压住圆环，大卡不在首屏**

360×800 的首屏是顶栏、文件夹、轮盘和圆环。Dock 固定在 y 712–776，圆环在 y 629–791，Dock 盖住圆环下半，绿色的 1 和红色的 0 从 Dock 底下露出来。标题 `Software Engineering` 在主题开关旁边断成 `Engineeri` / `ng`。中央大卡从 y 876 才开始，右栏收藏和禅模式入口在 y 1417。首屏既没有大卡，也没有禅模式入口。

规格第 13.3 节和第 16 节：360px 要能浏览、复习，圆环、Dock、收藏栏都够得着，并且不出现横向滚动。横向滚动这一条是达到的。

**4. Enter 不翻面**

在普通视图按 Enter，转子保持正面。点大卡可以翻面，反面正文为空时 DOM 里有 `This card has no content yet.`。

画廊的窗口监听只在 `t < 0.5`（全景档）处理 Enter。普通视图固定在聚焦档。FlipCard 自己的 Enter 会去翻内部状态，但画廊把 `flipped` 做成受控，又把 `onFlipChange` 传成空函数，所以这一下写不回画廊。规格第 4.2 节和第 13.1 节：点击和 Enter 都要翻面。

**5. 从右栏进禅模式，落到最早的那张卡，不是当前这张**

当时聚焦的是 Fighter（`/folder/…/c732d306-…`）。点右栏禅模式后地址是 `/zen/febde022-…`，没有卡片 id，画面上的标题是 `What is a requirement?`。Esc 退回来，也停在这张最早的卡上，不是 Fighter。

规格第 6 节：从右栏进来要聚焦普通视图当前那张卡；地址可以不带卡片 id，但卡不能换成最早的那张。`FileView` 写的是 `/zen/${folderId}`，`ZenView` 在没有 itemId 时用 `earliestIndex`。

### 19.2 接着修

**6. 再点轮盘里已经聚焦的那张卡，不会翻面**

点轮盘上的 Fighter，地址和中央标题都换成了 Fighter，正面没翻。再点这一行，转子仍是正面。规格第 16 节：点轮盘里的卡让画廊聚焦它；点当前聚焦的那张，翻面。`CardWheel` 的点击只调用 `onSelect`。

**7. 甩卡不跟手**

规格第 4.2 节：横向甩动，松手切到下一张；拖到一半松手回到原位。`ArcGallery` 的 `pointermove` 只记位移，不移动卡片。超过 12px 后，`pointerup` 一律 `stepCard(1)`，方向和记下来的速度都没用。这一条是读处理函数得到的，浏览器里没有单独做一次拖拽。

**8. 中央区域滚不动，Dock 不会收起**

1440 下 `.file-view__center` 的 `scrollHeight` 等于 `clientHeight`（都是 768）。规格第 5.4 节：主区向下滚，Dock 向下滑出屏幕；滚回来或鼠标靠近底部，Dock 再出现。处理函数写了，这一层没有可滚的距离，所以收起不会发生。

**9. 新建卡片没有进入编辑视图**

`handleCreateCard` 创建成功后 `navigate` 到 `/zen/${folderId}/${card.id}`。规格第 9.1 节：新建卡片进入和编辑同一类的视图，标题是 `New page`，正文为空。第 14 节 P2 只把那一屏的排版标成待设计，并没有改成进入禅模式。浏览器里没有执行创建，种子数据没有多一张卡。

**10. 删卡片的确认文案没有文件夹数**

点 Dock 的 Delete，对话框是：`Delete card “Fighter”? Delete this card? 1 card will be removed.` 点 Cancel 之后卡还在。规格第 9.3 节：确认文案要写出将去掉的文件夹数量和卡片数量。`removalConfirmText` 在卡片这条只写了卡片数。标题和正文还各说了一次 Delete。

**11. 面包屑点上去的第一下，地址用了上一层的卡片 id**

在 Integration（当时的卡片是 `33916663-…`）点面包屑 `Software Engineering`。中间地址变成 `/folder/febde022-…/33916663-…`，也就是父文件夹配上子层那张卡。随后才被改成父层最早的卡 `/folder/febde022-…/5d15d8e5-…`，标题回到 Software Engineering。最后落点是对的，中间这一下是错的：切层时选卡效果还拿着上一层的卡片列表，把那张卡的 id 写进了新文件夹的地址。
